# Design: M2.1 — Live AG-UI agent (OpenRouter)

**Status:** Planned (optional before or interleaved with M3).  
**GitHub:** [#10](https://github.com/Ensive/genui-lab/issues/10)  
**Depends on:** M2 fixture agent + inspector Protocol / Shared state surfaces.

## Goal

Replace (or sit beside) the fixture producer with a **real** AG-UI HTTP agent backed by OpenRouter, while keeping the same inspector semantics and Telemetry 001 task.

## Solution sketch

- `HttpAgent` (or equivalent) pointing at a small Node/serverless AG-UI endpoint in-repo (or documented external bridge)
- Auth via `OPENROUTER_API_KEY` in `.env.local` (see `.env.example`) — never commit secrets
- Same inspector: Protocol events, Shared state, interrupt/resume if the live agent emits them
- Fixture agent remains available as a **toggle** so demos/CI stay offline-capable (ADR-0002)

## Constraints

- Do not invent TTFT / tokens / cost until honestly measured from the provider
- Domain analysis may still be tool-backed and deterministic; the model should not become the source of truth for telemetry math
- AG-UI remains protocol, not a render mode (ADR-0003)

## Acceptance criteria

- [ ] Documented run path with and without API key (fixture fallback)
- [ ] Live run streams real AG-UI events into Protocol tab
- [ ] Honest usage metrics only when available; otherwise `null`
- [ ] E2e: offline fixture path still passes in CI without secrets
- [ ] README / AGENTS updated for env setup

## Out of scope

Declarative GenUI frameworks (M3), assistant-ui shell (M4), MCP Apps (M5).
